产品经理最容易浪费时间的环节是什么？我自己的答案是**写 PRD**——尤其是当一份 PRD 要在「业务方」和「研发」之间反复翻译时。

过去三个月我尝试把整个 PRD 写作流水线接到 AIGC 上，效果出乎意料：**从需求到初稿 PRD 的时间从原来的 4 小时压缩到 1 小时左右**，且大部分初稿可以直接进入评审环节。

## 我的工作流

### 1. 输入：原始需求录音转写

业务方的需求往往是语音或者零散的微信消息。我用 **飞书妙记 + GPT-4** 做第一轮结构化：

> Prompt 大意：「你是产品经理助理，请把以下对话转写为结构化需求清单，输出：业务背景、用户痛点、核心场景、非功能性需求、不确定项。」

输出后再人工校对一遍——AI 不能替代判断，但它能**消除 80% 的打字成本**。

### 2. 拆解：用 RICE 做优先级

把上面产出的需求清单丢给 LLM，让它按 **RICE 框架**（Reach / Impact / Confidence / Effort）打第一轮分。

> ⚠️ 这里有个坑：LLM 给的 Confidence 普遍偏高，必须人工根据历史数据修正。

### 3. 输出 PRD：Cursor + 项目模板

我维护了一个 PRD Markdown 模板放在 Cursor 里，包括：背景、目标指标、用户故事、功能清单、异常流、埋点需求、上线方案。

新写 PRD 时，Cursor 自动补全 + 我手动微调，比从空白文档写快得多。

### 4. 配图：Stable Diffusion 出 UI 概念图

以前这一步要么拖 UI 设计师、要么去 dribbble 截图。现在我用 SDXL + LoRA 出概念图，10 分钟一组，能覆盖 80% 的"早期对齐"场景。

## 我的反思

工具提效是真实的，但要小心两个陷阱：

1. **别让 AI 替你做判断**。它能加速「打字」，但不能加速「想清楚」。
2. **别让团队失去语言**。如果所有 PRD 都是 AI 写的，团队会失去对需求语言的控制力。

所以我现在的工作模式是：**AI 负责搬运和发散，我负责收敛和决策**。
